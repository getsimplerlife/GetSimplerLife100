# P0 #235 — merge-on-write for the credential store (stop the full-snapshot wipe of fresh connections)

## Problem (live-observed 2026-08-19)
The owner reconnected Xero at 18:46:21Z. The OAuth callback durably persisted the fresh token (`tenant_oauth_credentials.json#mathewortiz97@gmail.com:xero`) and live verification passed 23/26 against the durable store. Yet by ~19:56 the row was **removed from BOTH the Neon durable store and the local file** — an instance that booted before the reconnect held an in-memory snapshot without the Xero row, and its next **whole-object write** erased the key it didn't know about.

**Root cause:** the credential store is a single JSON object keyed `${email}:${provider}` and several writers did `writeJSON(file, <whole in-memory snapshot>)`. Any writer with a stale snapshot (token refresher tick, admin credential PUT/DELETE, generic OAuth callback) silently wipes rows added by other instances since the snapshot was taken. #234 fixed the READERS to be durable-first; the WRITE path was still destructive.

## Fix — merge-on-write everywhere
New shared helper in `src/lib/data-store.ts`:

- `mergeDurableCredential(file, mutations[])` — **read-live → mutate ONLY the intended key(s) → write → flush**. The live read uses `readJSONLive` (durable store → cache → file), so a writer can never clobber a row it didn't know about. **Fail-closed**: if the live value is not a plain object it throws instead of overwriting the store.

All credential-store writers now route through it:

| Writer | Before | After |
|---|---|---|
| `token-refresher.ts` `refreshOneCredential` | `writeJSON(file, tokenData)` — whole stale snapshot (the hot-path wiper) | merge-set for exactly the refreshed `key` |
| `token-refresher.ts` `sweepExpiredTokens` | `writeJSON(file, tokenData)` — whole snapshot | merge-set only for keys changed in this sweep |
| `prod-server.ts` admin `PUT credentials/<id>` | stale `readJSON` + whole write | live-read + merge-set for the one app-creds key |
| `prod-server.ts` admin `DELETE credentials/<id>` | stale `readJSON` + whole write | merge-delete for exactly that key |
| `prod-server.ts` generic OAuth callback | stale `readJSON` + whole write, **no durable flush** | live-read + set exactly one `tokenKey` + `await durableFlush()` before the connect response |

Already-safe writers verified unchanged: `persistOAuthTokenDurable` (#180, callback) and the portal Disconnect handler (#181) already read live and mutated only their key — they now share the same pattern.

## Tests (`src/test/merge-on-write.test.ts`, 6 new)
Reproduce the exact dangerous interleaving against a MemoryKvDriver-backed durable store:
- **(a)** store has {A,B}; a writer holding a snapshot with **only A** refreshes A → store still contains B (A updated, B byte-identical), app-creds survive, local file mirrors.
- **(b)** helper delete of B removes only B → A remains.
- **(c)** helper set of C adds C → A and B remain.
- **(d)** a NEWER key C lands in the store after the writer's snapshot was taken; the stale writer refreshes A → C is untouched (never deleted).
- **fail-closed**: corrupt non-object store value → helper throws, no partial write.
- durable-disabled plain-file path still set/delete correctly.
